PROJECT NAME: Gauntlet of Runes
  - "Gauntlet" = the sequence of 5 escalating monster fights
  - "Runes" = the magical moves/spells the hero collects along the way
  - Short, memorable, fits the RPG fantasy theme


--------------------------------------------------------------------------------
OVERVIEW
--------------------------------------------------------------------------------

Turn-based RPG where a Knight hero fights 5 monsters in a gauntlet.
Each fight the hero picks one of their moves; the monster responds with a move
fetched from the backend AI. On victory the hero learns one of the monster's
moves and keeps it for the rest of the run. Fights can be replayed for XP
which levels up the hero's base stats.

Hero stats: ATK, DEF, HP, MAG
Damage formula (physical): max(1, ATK * multiplier - enemy_DEF * 0.5)
Damage formula (magic):    max(1, MAG * multiplier) [ignores DEF]

BACKEND
--------------------------------------------------------------------------------

LOCATION: /backend/
FILES:
  main.py        — FastAPI app, 2 endpoints
  game_data.py   — All game constants + AI logic
  requirements.txt
  Procfile       — Railway/Render deployment

ENDPOINTS:

  GET /run/config
    No parameters.
    Returns: Full JSON with hero data, all 24 moves with effects, and 5
    monsters with their stats and move lists.
    Call: Once on game startup. Cache the result — never call again mid-run.

  GET /monster/move
    Query params:
      monster_id     (string)  — e.g. "goblin_warrior"
      monster_hp     (int)     — current HP
      monster_max_hp (int)     — max HP
      hero_hp        (int)     — current HP
      hero_max_hp    (int)     — max HP
      hero_atk       (int)     — current ATK including buffs/debuffs
      hero_def       (int)     — current DEF including buffs/debuffs
      hero_mag       (int)     — current MAG including buffs/debuffs
      last_move      (string?) — previous monster move id, for variety
      turn           (int)     — turn number, starts at 1
    Returns: { "move_id": "shadow_bolt" }
    Call: At the start of every monster turn.

AI LOGIC SUMMARY (in get_monster_ai_move):
  - Every available move gets a base weight of 1.0
  - Repeating the last move: weight * 0.15 (forces variety)
  - Monster HP < 30%: heals/drain_life get 4x, self-damage moves get 0.05x,
    defensive buffs get 2.5x
  - Hero HP < 35%: high-multiplier attacks get 3.5x (go for the kill)
  - Hero ATK > 14: ATK-debuff moves get 2.5x
  - Hero DEF > 12: DEF-strip moves get 2.5x
  - Turn 1: buff moves get 0.3x (always open with an attack)
  - Final pick: weighted random selection from the pool

--------------------------------------------------------------------------------
RECOMMENDED CLASS ARCHITECTURE (Unity C#)
--------------------------------------------------------------------------------

Organize under Assets/Scripts/ with these subfolders:
  Data/       — pure data classes, no MonoBehaviour
  Managers/   — MonoBehaviour singletons, one per scene
  UI/         — MonoBehaviour components attached to UI GameObjects
  Utils/      — helpers, no MonoBehaviour

----- DATA CLASSES (no MonoBehaviour, just [System.Serializable]) -----

GameConfig.cs
  Fields: HeroConfig hero, Dictionary<string,MoveData> moves, List<MonsterData> monsters
  Purpose: Deserialization root for /run/config JSON response.
  How: Use JsonUtility or Newtonsoft Json.NET. Newtonsoft is recommended
  because it handles Dictionaries natively — install via Package Manager
  (com.unity.nuget.newtonsoft-json).

HeroConfig.cs
  Fields: string id, string name, BaseStats baseStats, BaseStats statsPerLevel,
          List<string> starterMoves, int maxMoves
  Purpose: Holds the hero's baseline configuration from the server.

MonsterData.cs
  Fields: string id, string name, string description, int spriteRow,
          int spriteCol, BaseStats stats, List<string> moves,
          int xpReward, int difficulty
  Purpose: Read-only monster template from config. Never modified at runtime.

MoveData.cs
  Fields: string id, string name, string description, string type,
          string target, float atkMultiplier, float magMultiplier,
          float healPercent, List<StatChange> statChanges,
          DotEffect dot, bool lifesteal, int selfHeal, int selfDamage,
          float stunChance, string icon
  Purpose: Everything needed to resolve a move's effect.

StatChange.cs
  Fields: string stat, int amount, int duration
  Purpose: Represents a buff or debuff applied to ATK/DEF/HP/MAG.

DotEffect.cs
  Fields: int damage, int duration, string type (e.g. "poison")
  Purpose: Damage-over-time applied after the move.

BaseStats.cs
  Fields: int atk, int def, int hp, int mag
  Purpose: Reusable stat block for hero and monsters.

BattleStats.cs
  Fields: int currentHp, int maxHp, int currentAtk, int currentDef,
          int currentMag, List<ActiveModifier> activeModifiers,
          DotEffect activeDot
  Methods: ApplyModifier(StatChange), TickModifiers(), TickDot(),
           GetEffectiveStat(string), Reset(BaseStats)
  Purpose: Mutable runtime stats for one combatant. Separate from the
  read-only MonsterData/HeroConfig. This is what changes every turn.

ActiveModifier.cs
  Fields: string stat, int amount, int turnsRemaining
  Purpose: One active buff or debuff with a countdown.

HeroProgress.cs
  Fields: int level, int currentXp, int xpToNextLevel,
          List<string> learnedMoveIds, List<string> equippedMoveIds,
          BaseStats currentBaseStats
  Methods: AddXp(int), LevelUp(), LearnMove(string), EquipMove(string)
  Purpose: Persistent hero state across fights. This is what you'd save
  to PlayerPrefs or a save file for persistence between sessions.


----- MANAGER CLASSES (MonoBehaviour, singletons via Instance pattern) -----

GameManager.cs  (DontDestroyOnLoad)
  Fields: GameConfig config, HeroProgress heroProgress
  Methods: StartRun(), LoadConfig()
  Purpose: Top-level orchestrator. On startup calls ApiClient.GetConfig(),
  stores the result, then loads the battle scene with the first monster.
  Holds HeroProgress across the entire run.
  How: Static Instance. On Awake, call StartCoroutine(LoadConfig()).

ApiClient.cs  (MonoBehaviour or static utility)
  Fields: const string BASE_URL = "https://your-railway-url.up.railway.app"
  Methods: IEnumerator GetConfig(Action<GameConfig> callback),
           IEnumerator GetMonsterMove(MonsterMoveRequest req, Action<string> callback)
  Purpose: All HTTP calls in one place. Uses UnityWebRequest.
  How: Use JsonUtility.FromJson<T>() or Newtonsoft for parsing.
  Error handling: if request fails, retry once, then fallback to local
  weighted-random so the game never hard-blocks on a network error.

  MonsterMoveRequest.cs (helper struct)
    Fields: string monsterId, int monsterHp, int monsterMaxHp, int heroHp,
            int heroMaxHp, int heroAtk, int heroDef, int heroMag,
            string lastMove, int turn
    Method: string ToQueryString()

BattleManager.cs  (one per battle scene)
  Fields: MonsterData currentMonster, BattleStats heroStats, BattleStats monsterStats,
          int currentTurn, string lastMonsterMove, bool isHeroTurn,
          List<string> heroMoves
  Methods: StartBattle(MonsterData), OnHeroMoveSelected(string moveId),
           ExecuteHeroMove(MoveData), RequestMonsterMove(), ExecuteMonsterMove(MoveData),
           ResolveDamage(MoveData, BattleStats attacker, BattleStats defender),
           ResolveBuffDebuff(MoveData, BattleStats target),
           ResolveDot(BattleStats target), CheckBattleEnd(),
           OnVictory(), OnDefeat()
  Purpose: The heart of the game. Drives the turn loop:
    1. Show hero move buttons → wait for input
    2. Execute hero move, apply effects, tick DOTs and modifiers on monster
    3. Call ApiClient.GetMonsterMove() with current state
    4. Execute monster move, apply effects, tick DOTs and modifiers on hero
    5. Increment turn, check win/lose
  How: State machine using an enum (HeroTurn, WaitingForMonsterMove,
  MonsterTurn, BattleOver). Coroutines for timing/animation waits.

MoveEffectProcessor.cs  (static utility class)
  Methods:
    static int ResolvePhysicalDamage(MoveData move, BattleStats atk, BattleStats def)
      Formula: max(1, Mathf.RoundToInt(atk.currentAtk * move.atkMultiplier
                                       - def.currentDef * 0.5f))

    static int ResolveMagicDamage(MoveData move, BattleStats atk)
      Formula: max(1, Mathf.RoundToInt(atk.currentMag * move.magMultiplier))

    static int ResolveHeal(MoveData move, BattleStats target)
      Formula: Mathf.RoundToInt(target.maxHp * move.healPercent)

    static void ApplyStatChanges(MoveData move, BattleStats target)
    static bool RollStun(MoveData move)   // Random.value < move.stunChance
  Purpose: Pure functions with no side effects. BattleManager calls these
  then applies the returned values to BattleStats.

GameProgressManager.cs  (DontDestroyOnLoad)
  Fields: int currentMonsterIndex, bool[] monstersDefeated (5 slots)
  Methods: OnMonsterDefeated(int index), GetNextMonster(), CanReplayFight(int index)
  Purpose: Tracks which monsters are beaten and what replay is allowed.
  Lives on GameManager or as its own singleton.


----- UI CLASSES (MonoBehaviour on UI GameObjects) -----

BattleUIController.cs
  Fields: HealthBarUI heroHealthBar, HealthBarUI monsterHealthBar,
          StatDisplayUI heroStats, StatDisplayUI monsterStats,
          MoveButtonPanel moveButtonPanel, BattleLogUI battleLog,
          CombatantDisplay heroDisplay, CombatantDisplay monsterDisplay,
          GameObject resultPanel
  Methods: SetupBattle(MonsterData monster, HeroProgress hero),
           UpdateHealthBars(), ShowDamageNumber(int dmg, bool isHero),
           ShowMoveResult(string moveName, string effectText),
           ShowModifierApplied(string stat, int amount, bool positive),
           LockMoveButtons(), UnlockMoveButtons(),
           ShowVictory(string learnedMove), ShowDefeat()
  Purpose: Purely visual. BattleManager calls these methods to reflect
  state changes. No game logic lives here.

MoveButtonPanel.cs
  Fields: List<MoveButton> buttons
  Methods: Populate(List<string> moveIds, Dictionary<string,MoveData> allMoves),
           SetInteractable(bool), OnMoveClicked(string moveId) [event/callback]
  Purpose: Renders the 4 move buttons with icon, name, and type color.
  Wires each button's onClick to BattleManager.OnHeroMoveSelected().

MoveButton.cs
  Fields: Image icon, TMP_Text moveName, Image background, string moveId
  Methods: Setup(MoveData move, Sprite iconSprite), SetHighlight(bool)
  Purpose: Single move button component. Color-code by type:
    physical = warm orange, magic = purple, buff = green, heal = teal.

HealthBarUI.cs
  Fields: Slider slider, TMP_Text hpText, Image fillImage
  Methods: SetMax(int maxHp), UpdateHP(int currentHp, bool animated)
  Purpose: Animated HP bar. Use DOTween or a simple Lerp coroutine.

CombatantDisplay.cs
  Fields: SpriteRenderer spriteRenderer, Animator animator
  Methods: SetSprite(Texture2D sheet, int row, int col, int spriteSize=32),
           PlayHitAnimation(), PlayAttackAnimation(), PlayDeathAnimation()
  Purpose: Loads the correct sprite from the sheet by computing the
  pixel rect: new Rect(col*32, sheet.height - (row+1)*32, 32, 32)
  and creating a Sprite from it at runtime.

BattleLogUI.cs
  Fields: TMP_Text logText, ScrollRect scroll
  Methods: AddEntry(string text), Clear()
  Purpose: Scrolling combat log showing what happened each turn.

StatDisplayUI.cs
  Fields: TMP_Text atkText, defText, magText
  Methods: Refresh(BattleStats stats)
  Purpose: Shows current ATK/DEF/MAG numbers (green if buffed, red if debuffed).

MoveLearnUI.cs
  Fields: GameObject panel, TMP_Text moveNameText, TMP_Text moveDescText,
          Image moveIcon, Button confirmButton
  Methods: Show(MoveData newMove, List<string> currentMoves, Action<string> onReplace)
  Purpose: Post-victory screen where player picks which current move to replace
  with the newly learned monster move (if they already have 4 moves).

SpriteManager.cs  (static utility or ScriptableObject)
  Methods:
    static Sprite GetSprite(Texture2D sheet, int row, int col, int size=32)
    static Sprite LoadIcon(string iconName)   // loads from required_icons/
  Purpose: Central sprite loading. Cache loaded sprites in a Dictionary to
  avoid re-slicing the sheet every time.


----- SCENE STRUCTURE -----

  Scene 1: MainMenu
    - Play button → calls GameManager.StartRun()
    - Shows hero stats / current level if returning player
    - ApiClient fetches /run/config here

  Scene 2: Battle
    - One scene reused for all 5 monsters (and replays)
    - GameManager passes MonsterData to BattleManager on scene load
    - On victory: show MoveLearnUI, then load next monster or RunComplete scene

  Scene 3: RunComplete (optional, simple)
    - Shows final stats, XP earned, moves learned across the run
    - Play Again button resets HeroProgress for a new run

UNITY TIPS
--------------------------------------------------------------------------------

COROUTINE PATTERN FOR TURN LOOP (BattleManager):
  The cleanest approach is a single coroutine that drives the whole battle:

  IEnumerator BattleTurnLoop() {
      while (!isBattleOver) {
          // Hero turn
          ui.UnlockMoveButtons();
          yield return new WaitUntil(() => heroMoveChosen);
          ui.LockMoveButtons();
          yield return StartCoroutine(ExecuteHeroMove(chosenMove));
          if (isBattleOver) break;

          // Monster turn
          string moveId = null;
          yield return StartCoroutine(apiClient.GetMonsterMove(BuildRequest(),
              result => moveId = result));
          yield return StartCoroutine(ExecuteMonsterMove(moveId));
      }
      HandleBattleEnd();
  }

  Set heroMoveChosen = true in OnHeroMoveSelected(), reset at start of each turn.

SPRITE EXTRACTION AT RUNTIME (CombatantDisplay):
  Texture2D sheet = Resources.Load<Texture2D>("Sprites/monsters");
  float pw = 1f / (sheet.width / 32f);   // normalized width
  float ph = 1f / (sheet.height / 32f);  // normalized height
  // Note: Unity UV origin is bottom-left, sprites.txt is top-to-bottom
  int totalRows = sheet.height / 32;
  int flippedRow = totalRows - 1 - row;
  Rect rect = new Rect(col * 32, flippedRow * 32, 32, 32);
  Sprite s = Sprite.Create(sheet, rect, new Vector2(0.5f, 0.5f), 32f);
  spriteRenderer.sprite = s;

JSON DESERIALIZATION WITH NEWTONSOFT:
  using Newtonsoft.Json;
  GameConfig config = JsonConvert.DeserializeObject<GameConfig>(jsonString);
  // Handles Dictionary<string,MoveData> automatically.
  // JsonUtility does NOT support Dictionaries — use Newtonsoft.

STAT MODIFIER TICK (call at end of each full round):
  foreach (var mod in stats.activeModifiers.ToList()) {
      mod.turnsRemaining--;
      if (mod.turnsRemaining <= 0) {
          stats.RevertModifier(mod);
          stats.activeModifiers.Remove(mod);
      }
  }
